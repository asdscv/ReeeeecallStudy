# 플래시카드·시험·게임 로직 감사

## 재현과 수정

- **플래시카드** 순차 학습에서 카드 3장을 평가해도 완료 이력에 0장이 기록됐다. 기존 서버는 웹과 앱이 보내는 `known`과 `unknown`을 거절했다. 마이그레이션 291에서 순차·랜덤·날짜별 학습의 두 평가를 허용했다. 기존 `next` 요청도 처리한다.
- **플래시카드** 다시 볼 카드가 평가 도중 복귀하면 방금 화면에서 읽은 카드와 서버에 평가하는 카드가 달랐다. 화면에 제시한 카드를 평가 완료까지 고정하고, 같은 카드의 후속 저장은 서버가 반환한 리비전을 사용한다. 하루 계획과 오답 복습은 선택 순서대로 진행하며 보관·중지된 카드를 제외한다.
- **플래시카드** 두 학습 화면을 빠르게 열면 이전 요청이 다른 덱의 화면과 상태를 덮어썼다. 세션을 구분해 이전 완료 응답은 원래 세션에만 반영한다. 벼락치기 타이머는 평가나 되돌리기 응답이 끝난 뒤 종료할 수 있고, 완료한 하루 계획을 다시 열면 돌아가기 버튼을 제공한다.
- **시험** 연속 제출에서 두 건의 요청이 전송됐고, 이전 회차 조회가 늦으면 다른 회차에 그 문항이 나타났다. 답안 저장·채점·종료·다시 응시는 요청 중 한 번만 실행한다. 조회 응답은 현재 요청한 회차에 반영한다.
- **게임** 마감 시각을 넘겨 누르면 타이머 콜백보다 먼저 정답 처리되는 경우가 있었다. 입력과 타이머가 같은 마감 시각을 검사한다. 숫자 야구의 상위 20단계는 시간이 끝나면 실패를 기록하고 답을 표시한다.
- **모바일** iOS 실행 중 존재하지 않는 `answer_timing` 필드를 조회해 프로필 설정 전체를 읽는 요청이 실패했다. 해당 필드 요청과 저장할 수 없던 평가 시점 선택을 제거했다.

## 검증

- 로컬 Chromium과 Supabase에서 플래시카드 6개 모드의 카드 평가와 기록, SRS 되돌리기, 하루 계획 완료 후 재진입을 확인했다.
- 객관식 정답 셔플·자동 채점·연속 제출·재응시, 단답형과 서술형 답안 저장·새로고침·완료를 확인했다. 실제 외부 AI 생성·채점 호출에는 비용을 발생시키지 않았다.
- 게임 12개를 브라우저에서 열었다. 숫자 찾기는 플레이·일시 정지·재개·결과와 클라우드 저장을 확인했다. 게임 엔진에서 화면 크기 3종, 전 난이도, 시드 4개씩 정답 진행 6,600건과 시간 초과 종료 6,216건을 검증했다. 수정 전에는 숫자 야구 시간 초과 240건이 종료되지 않았다.
- 로컬 HTTP 동시 요청을 각 32건씩 보냈다. 같은 카드 평가 재전송은 로그 1건, 시험 시작은 고유 회차 번호 32개, 게임의 같은 리비전 저장은 성공 1건과 충돌 응답 31건이었다.
- iOS 시뮬레이터에서 로그인, 순차 학습 평가 3건과 완료, 시험 제출과 결과, 게임 입력과 일시 정지·재개를 확인했다. Android는 번들 생성으로 확인했다.
- 웹 Vitest 4,387건, Supabase HTTP 통합 46건, SQL 25개 스위트를 통과했다. 웹 빌드와 모바일 타입 검사도 통과했다.

## 적용 순서

운영 웹 배포 전 Supabase에 마이그레이션 291을 적용한다. 기존 호출 시그니처를 유지한다. 롤백은 같은 함수의 평가값 검증을 복구하며 저장된 기록을 보존한다.

2026-11-21 운영 DB에서 291 적용과 스모크 검증을 완료했다. 테스트 트랜잭션은 롤백했다.
