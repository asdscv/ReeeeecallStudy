## 1. 그런데 유입만 문제가 아니었다

온보딩 진행 기록(`onboarding_progress`)을 외부 사용자 기준으로 집계하면:

```
welcome      15명
createDeck   12명
addCards      0명
firstStudy    0명
exploreMarket 0명
```

**첫 학습에 도달한 사람이 한 명도 없다.** 9/25 아침에 들어온 실제 신규 사용자도
`welcome` 02:38:05 → `createDeck` 02:38:07 → 이탈. 2초였다.

원인은 두 가지였고 둘 다 고쳤다.

1. **온보딩이 "덱을 만들어라"로 시작했다.** 가입 직후 계정은 아무것도 소유하지 않는데
   덱 생성 → 템플릿 선택 → 카드 입력을 요구했다. 공식 덱 649개는 등장하지 않았다.
2. **웹 온보딩은 한 번도 뜬 적이 없다.** `onboarding-store`의 `isCompleted`가 깜빡임 방지용으로
   `true`에서 출발하는데 `initialize()`가 그 값으로 가드를 걸어서, 서버에 묻기도 전에 리턴했다.
   `showOnboarding`은 영원히 false였다. (모바일은 RPC를 직접 불러서 정상 동작했다 —
   위 15/12명은 사실상 전부 앱 사용자다.)

## 2. 촬영 대본 — 사진 → 덱 (15초)

퍼질 수 있는 기능은 이것 하나다. 설명이 필요 없고, 결과가 화면에 그대로 보인다.

**준비물**: 손글씨 필기 또는 교과서 한 페이지(영어 단어가 보이는 것), 실기기 1대.
녹화는 세로 1080×1920. 자막은 화면에 태우고, 음성은 넣지 않는다(무음 재생이 기본이다).

| 초 | 화면 | 자막 |
|---|---|---|
| 0–2 | 책상 위 필기 노트를 손으로 편다. 앱은 아직 안 보인다. | `이거 외워야 하는데` |
| 2–4 | 앱을 열고 AI 생성 → 이미지 선택 | (없음) |
| 4–6 | 노트를 카메라로 찍는다. **셔터음이 들리게.** | `사진 한 장` |
| 6–10 | 생성 진행 표시 → 카드 목록이 채워진다. **여기서 배속 금지.** 실제 소요를 보여준다. | `카드가 생겼다` |
| 10–13 | 첫 카드를 넘기고 정답을 누른다 | (없음) |
| 13–15 | 덱 화면. 카드 수가 보인다. | `앞으로 매일 이 단어들이 돌아온다` |

**함정**
- 생성 시간을 잘라내면 안 된다. 실제보다 빨라 보이면 첫 사용에서 배신감을 준다.
- 카드 내용이 실제로 읽히는 필기를 써야 한다. 흐릿한 사진은 AI가 틀리고, 그 화면이 그대로 남는다.
- 경쟁 서비스 이름을 화면·자막·설명 어디에도 넣지 않는다.
- "무제한"이라고 쓰지 않는다. 캡이 있는 단위는 카드다.

## 3. 아직 열려 있는 것

  적었던 것은 틀렸다. `native_language` 컬럼만 보고 판단했다.)

  역방향 덱 **327개 / 192,548장**이 앞면에 한국어·중국어·일본어·베트남어·스페인어·
  인도네시아어·태국어를, 뒷면에 영어를 담고 있다. 예문도 양쪽 언어로 다 있다:

  ```
  front: 안녕하세요            back: hello
  example_front: 안녕하세요, 오늘 어떠세요?
  example_back:  Hello, how are you today?
  ```

  영어 화자에게 이것은 **한국어를 배우는 덱**이다. 그대로 쓸 수 있다.

  막는 것은 메타데이터다. `DeckMetadataI18n.ts` 의 설계 규칙이 "덱의 표시 언어는 언어쌍의
  **비영어 쪽**"이고, 순방향(en→X)·역방향(X→en)·회화 덱 전부 X 로 렌더된다. 그래서
  역방향 덱도 제목이 한국어이고 `native_language='ko'`, `learning_language='en'` 이다.
  결과적으로 영어 화자가 필터로 잡을 수 있는 덱은 **0개**다:

  ```
  native_language='en'            0
  learning_language='ko'          0
  learning_language <> 'en'       0
  ```

  `DeckMetadataI18n.ts` 에는 `en: { ko: "Korean", ja: "Japanese", … }` 행이 **이미 있다** —
  영어 제목을 만드는 기계는 갖춰져 있고 `audienceLanguage()` 가 영어를 반환하지 않을 뿐이다.

  단서 하나: 이 단어 목록은 *한국인이 영어를 배울 때 필요한* 빈도순으로 골라진 것이라,
  한국어 쪽은 그 번역이다. 영어 화자를 위해 설계된 한국어 코스는 아니다. 부산물이지만
  35,222장은 실재하는 콘텐츠다.
- **App Store 노출수**: ASC에서 Admin 권한 키를 새로 발급하거나(애널리틱스 API),

  온보딩 블록은 이번에 전부 번역했지만 나머지는 남아 있다. 공식 덱이 바로 그 7개 언어를 향한다.

## 숫자를 다시 볼 때 쓸 쿼리

내가 한 번 틀렸던 자리라 그대로 붙여 쓸 수 있게 적어 둔다. Management API 로 돌린다
(`POST /v1/projects/<ref>/database/query`, 자격증명은 [[reference_credentials]]).

```sql
-- 1) 유입: 주별 신규 가입 (내부/테스트 계정 제외)
SELECT date_trunc('week', created_at)::date AS wk, count(*)
FROM auth.users
WHERE email !~* '(test|e2e|uitest|demo|\+|rictax\.kr|asdscv)'
GROUP BY 1 ORDER BY 1 DESC LIMIT 8;

-- 2) 온보딩 퍼널: 어디서 멈추는가
SELECT o.step_key, count(*) AS reached
FROM onboarding_progress o JOIN auth.users u ON u.id = o.user_id
WHERE u.email !~* '(test|e2e|uitest|demo|\+|rictax\.kr|asdscv)'
GROUP BY 1 ORDER BY 2 DESC;

-- 3) 실제 학습.  user_card_progress 행 수를 세지 말 것 --
--    acquire_listing 이 구독할 때 카드마다 한 행씩 심는다.
SELECT u.email, ss.study_mode, ss.cards_studied, ss.started_at
FROM study_sessions ss JOIN auth.users u ON u.id = ss.user_id
WHERE u.email !~* '(test|e2e|uitest|demo|\+|rictax\.kr|asdscv)'
ORDER BY ss.started_at DESC LIMIT 20;

-- 3b) 카드 단위로 보고 싶으면 복습된 것만
SELECT count(DISTINCT user_id) AS studiers, count(*) AS reviewed_cards
FROM user_card_progress WHERE last_reviewed_at IS NOT NULL;

-- 4) 선반이 제대로 채워지는가 (기대: 비영어권 5, 영어권 0 + 픽커로 고른 만큼)
SELECT u.email, count(s.id) AS shelf
FROM auth.users u LEFT JOIN deck_shares s ON s.recipient_id = u.id
WHERE u.created_at > now() - interval '14 days'
GROUP BY 1 ORDER BY 2 DESC;
```

**함정 하나만 기억하면 된다: `user_card_progress` 행 수는 학습이 아니다.**
프로덕션 16,604 행 중 실제 복습은 1 행이었다.
